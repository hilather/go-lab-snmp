# LabSNMP 1.1.0 Release Notes

Release date: 2026-09-05
Previous release: 1.0.0
Application version: 1.1.0
Configuration versions: labsnmp.dev/v1alpha1
REST versions: /v1
MCP protocol versions: 2026-07-28
Container digest: see GHCR package for this tag (publish-image job summary)

## Highlights

RFC 3430 SNMP-over-TCP with BER-length framing (not a 32-bit prefix).
DTLS 1.2 record layer on IANA 10161/10162 wrapping community/USM PDUs
(not TLSTM/TSM). GHCR multi-arch `linux/amd64` + `linux/arm64`.
INFORM acknowledgements increment `InformAck` before `WriteTo`.
Reset rebinds UDP agent and trap sockets (bind-new-first).

TLS-001 is no longer deferred. `tcp.enabled` / `dtls.enabled` validate.

## Added

- RFC 3430 TCP agent and trap listeners (`internal/snmpwire` `ReadTCP`
  / `WriteTCP` frame one SNMP SEQUENCE by identifier+length). A framed
  Get starts with `0x30`. TCP-only (UDP off) is supported. INFORM and
  v3 Report ack is `Write` / `WriteTCP` on the accepted connection,
  never Dial.
- DTLS 1.2 record layer (pion/dtls v3.1.8) on IANA 10161/10162 with
  file-ref certs. Inner PDU stays community or USM. **TLSTM/TSM is
  not implemented.**
- TCP/DTLS listener fields are schema-legal: `tcp.enabled` /
  `dtls.enabled` validate under per-listener address rules and
  file-ref certs. Snapshot compiles those fields. Ready overlays Off
  from the active snapshot. `GET /v1/status` may list `agent-tcp` /
  `traps-tcp` / `agent-dtls` / `traps-dtls`. Gauge
  `labsnmp_listeners_bound`. `labsnmp serve --dtls-listen` /
  `--dtls-trap-listen`. Bind failure of any enabled listener is
  exit 1. Image `EXPOSE 161/tcp 162/tcp` (not `10161/udp`).
- Operator SPA Status and Overview show Agent TCP / Agent DTLS when
  `status.listeners` includes them. Features page still twelve ids.
  No new capability IDs.
- GHCR publish on `v*` is a multi-arch manifest list (`linux/amd64`,
  `linux/arm64`). CI unit jobs stay amd64; arm64 is publish-only.
  Digest of the manifest list is the pin.
- INFORM `InformAck` increments before `WriteTo` so the counter
  cannot race the reply. Store-then-ack is unchanged (ADR 0007).
- Reset rebinds UDP agent and trap sockets (bind-new-first). Changing
  bootstrap `listeners.agent.address` / `traps.address` then Reset
  moves the PacketConn.

## Residual

- Not a production agent. Not snmpd. Not a manager.
- No SMIv2 compiler. Numeric OIDs + optional aliases.
- v3 algs: MD5/SHA-1/SHA-256 + DES/AES-128 only.
- No AgentX. No trap forward or originate.
- DTLS is a record layer on IANA 10161/10162; inner PDU is community
  or USM. **TLSTM/TSM is not implemented.** pion/dtls v3.1.8 does not
  fragment DTLS application data and reads UDP into 8192 bytes, so a
  ≥8KiB SNMP Response cannot round-trip on DTLS.
- RFC 6353 TLS-over-TCP (snmp-tls) is residual. No `spec.listeners.tls`.
  Catalog code `tls_unsupported` is retained for that residual and is
  not emitted on `tcp`/`dtls` enable.
- Trap remoteAddr is best-effort under Docker userland-proxy
  (**NAT collision** does not affect split-horizon; identity is
  community/user, not client IP).
- Single replica. Memory store only. Overlay and trap inbox wipe on
  reset/restart.
- No OAuth PRM.
- Integrator pin in mcp-integration-lab is out of band.

See [docs/known-limitations.md](../known-limitations.md).

## Deployment and operations

Image `ghcr.io/hilather/labsnmp:v1.1.0` and `sha-<7 hex>`. v1.1.0
publishes a multi-arch manifest; digest pin is the manifest list.
Scratch, UID 65532, HEALTHCHECK exec form, CMD
`--management-listen=:8088`. Host residual 10161/udp, 10162/udp,
18161/tcp. Appliance smoke uses `:1161`/`:1162` with `cap_drop: ALL`.
Lab overlay keeps `tcp.enabled` / `dtls.enabled` false.

Do not git tag until required CI jobs on the exact SHA are green.
